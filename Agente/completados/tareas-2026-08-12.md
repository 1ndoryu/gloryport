## 128A-1 — GLORYPORT v1 (bandeja + CLI, Rust/Win32)

**Qué se hizo**: creación desde cero de GLORYPORT en `C:\Users\Owner\OneDrive\Documentos\area-trabajo\GLORYPORT`,
una herramienta solo Windows tipo port-killer con bandeja del sistema, minimalista y de bajo
consumo: escáner `GetExtendedTcpTable` (IPv4+IPv6), kill por PID con `OpenProcess`/
`TerminateProcess`, menú de bandeja con notificaciones, auto-inicio HKCU, single-instance,
CLI `list`/`kill`/`--version`, icono embebido y documentación (arquitectura, roadmap, plan).

**Archivos**:

  `src/autostart.rs`, `src/icon.rs`

**Decisiones / gotchas**:

- Stack elegido: Rust + crate `windows` 0.62.2 (features acotadas), un solo binario con
  `windows_subsystem = "windows"`; sin tokio, sin Electron, sin procesos externos.
- Escaneo bajo demanda (menú o CLI), sin timers: CPU ~0 % en reposo.
- Caché de nombres de proceso con TTL 10 s y tope 512 entradas.
- Kill protegido: nunca termina PID 0, PID 4 (System) ni el propio proceso.
- Salida tolerante a broken pipe (macros `outln!`/`errln!` en `cli.rs`): PowerShell cierra la
  tubería de un binario de subsistema gráfico y un `println!` estándar paniqueaba
  (os error 232); ahora la escritura se omite sin panico. En `cmd` y en llamadas
  programáticas la salida es completa.
- Compresión IPv6: `ipv6_to_string` devolvía `[]` para `[0;16]`; corregido para emitir
  `[::]` (caso cubierto por test unitario).
- Revisión de supervisor (`supervisor_reviewer`): **aprobar con observaciones**; se
  aplicaron en el mismo bloque: item "Actualizar lista" ahora re-escanea y reabre el menú
  (antes era no-op), cifra de RAM documentada con rango real (privada vs WorkingSet) y
  mejoras P2/P3 registradas en el roadmap (`128A-5`, `128A-6`).
- El shim `cargo` del entorno usa `C:\tmp\glory-target` como target dir (ruta del binario
  release en esta máquina).

**Prevención / Sentinel**: no aplica gate declarado en este proyecto (AGENTS.md local define
fmt+clippy+test+E2E como gate canónico).

**Pendientes reales**: validación de uso prolongado de la bandeja; fases P5/P6 del roadmap

## 128A-7 — Popup Wispr Flow (bandeja) y fix del clic físico del icono

**Qué se hizo**: el menú nativo (`TrackPopupMenu`) se reemplazó por un popup propio
estilizado con GDI siguiendo la referencia Wispr Flow (paleta `#ffffeb`/`#1a1a1a`/
`#f0d7ff`/`#034f46`/`#e4e4d0`, fuentes Figtree 400/500/600 + EB Garamond 400 embebidas con
`AddFontMemResourceEx`, layout compacto de 300 px, máx. 8 filas visibles con scroll de
rueda, insignia `N TCP`/`N+ TCP`). Se corrigió el bug por el que el clic físico en el icono
no abría el popup y se añadió robustez a la bandeja.

**Archivos**:

- `src/popup.rs` (nuevo) — popup GDI: layout, hit-test, hover, scroll, acción por clic,
  cierre por Esc / segundo clic / pérdida de foco.
- `src/fonts.rs` (nuevo), `assets/fonts/` (TTFs + OFL), `tools/make-fonts.py` (nuevo).
- `src/tray.rs` — usa `popup::show`, fix de `lParam` (palabra baja), re-agrega icono en
  `TaskbarCreated`, sin `SetCapture`.
- `src/main.rs` — DPI per-monitor v2 y módulos `fonts`/`popup`.
- `src/ports.rs`, `Cargo.toml` — se retira `menu_label`; features Win32 de UI.
- `assets/popup.png`, `README.md`, `docs/arquitectura.md`, `AGENTS.md`.

**Evidencia / gate** (todo verde):

| Chequeo | Resultado |
|---|---|
| `cargo fmt` + `cargo clippy --all-targets -- -D warnings` | OK |
| `cargo test` | 23/23 OK (20 unit —incluye layout/hit-test del popup— + 3 E2E) |
| `cargo build --release` | OK, 348.160 bytes |
| Smoke físico (release) | clic real sobre el icono vía `SendInput` → popup visible en ~25 ms, estable a 300 ms, 2.º clic cierra sin reabrir |
| Clic derecho | alterna el popup igual que el izquierdo (`WM_CONTEXTMENU`) |

**Decisiones / gotchas**:

- Con `NOTIFYICON_VERSION_4`, `lParam` del callback de bandeja = `(uID << 16) | mensaje`;
  el handler compara `lParam & 0xFFFF`. El bug pasó los tests por `PostMessage` con
  `lParam` limpio (sin id en palabra alta) mientras el clic real iba empaquetado.
- El popup **no captura el ratón**: con captura, el 2.º clic en el icono cerraba el popup y
  el `WM_LBUTTONUP` del shell lo reabría al instante. Sin captura, el 2.º clic alterna y el
  cierre por clic fuera se delega a `WM_ACTIVATE` (`WA_INACTIVE`), como menú nativo.
- `SendInput` para smoke: las coordenadas absolutas van normalizadas (0–65535) y el flag de
  movimiento es `MOUSEEVENTF_MOVE|ABSOLUTE` (0x8001); un test con píxeles crudos movía el
  cursor a otro sitio y no ejercitaba el icono.
- `TaskbarCreated` (mensaje registrado) re-agrega el icono si Explorer se reinicia; los
  iconos fantasma de procesos terminados a la fuerza siguen siendo fricción del shell.

**Prevención / Sentinel**: no aplica gate declarado en el proyecto. Fricción registrada en
roadmap `128A-8` (iconos fantasma tras cierres forzados).

**Pendientes reales**: `128A-8` — mitigación de iconos fantasma en la bandeja; validación
del popup en uso diario (DPI 125/150 %, alto contraste).
